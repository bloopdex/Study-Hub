Searching

Seven ways to find something in an array. Linear search works on anything in $O(n)$. The others use order (sorted, rotated, evenly spread, or hill-shaped) to throw away big parts of the array with each comparison and reach $O(\log n)$ or better.

Why it matters: the question "what do I know about my data?" decides the speed. The same lookup can take a million comparisons or twenty.

    The seven searches

    Linear search

    Check every element in order until you find it.

    O(n) worst · any order · O(1) space

    Study

    Binary search

    Check the middle, throw away half, repeat.

    O(log n) worst · sorted · O(1) space

    Study

    Interpolation search

    Guess the position from the value, like a phone book.

    O(log log n) avg · O(n) worst · sorted + uniform

    Study

    Exponential search

    Double the index to bracket the target, then binary search.

    O(log i) · sorted · unknown size OK

    Study

    Ternary search

    Two probes, keep one third; best for hill-shaped functions.

    O(log n) · sorted or unimodal · more comparisons than binary

    Study

    Rotated array search

    One half is always sorted: test the target against it.

    O(log n) · rotated sorted · distinct values

    Study

    Peak finding

    Walk uphill from the middle to reach a local peak.

    O(log n) · any array · finds a peak, not the max

    Which one to pick?

  B -->|"sorted but rotated"| R["Rotated array search"]
  B -->|yes| C{"Size unknown, or target near the front?"}

  C -->|no| D{"Values evenly spread?"}

  D -->|"no / not sure"| BS["Binary search"]

    Key points

    • Linear search is the only one with no data requirement, because it never assumes anything about unchecked elements.
    • Binary, exponential and rotated-array search are $O(\log n)$ because order lets one comparison discard half the range.
    • Interpolation search can reach $O(\log \log n)$ because it guesses the position from the value, but only on evenly spread data.
    • Ternary search loses to binary search on arrays because its 2 comparisons per round outweigh the bigger cut; it wins on hill-shaped functions.
    • Peak finding is $O(\log n)$ on unsorted data because it only needs a local peak, and the uphill side always has one.

    Video talking points

    Use these 5 bullets as your script outline. Say each one in your own words. Do not read them: glance at them and speak.

    1. Hook (10 sec). Ask: why does a phone book let you find any name in seconds, while a pile of unsorted cards does not?
    2. The big picture (30 sec). Linear search works on anything in $O(n)$. Every faster search uses some structure: sorted order for binary, interpolation, exponential and ternary search, a single rotation, or the slope for peak finding.
    3. Order is the key (30 sec). Sorting once costs $O(n \log n)$, but then each lookup is $O(\log n)$. Many lookups pay for the sort; one lookup does not.
    4. How to choose (45 sec). Walk the "Which one to pick?" flowchart: unsorted data, linear; sorted, binary; sorted and evenly spread, interpolation; unknown size or target near the front, exponential; rotated, the rotated variant; any array with a local peak, peak finding.
    5. One takeaway (10 sec). Every fast search throws away part of the data with each comparison; the structure of the data decides how much.
