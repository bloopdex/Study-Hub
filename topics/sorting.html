Sorting

Six classic ways to put things in order. Three are simple and run in $O(n^2)$. Three are clever and run in $O(n \log n)$, the best a comparison sort can do.

Why it matters: sorting is the first step of countless other algorithms, such as binary search, deduplication and merging, and it is where you learn the vocabulary of best, worst, stable and in-place.

    The six algorithms

    Bubble sort

    Swap neighbours that are out of order until nothing moves.

    O(n²) worst · stable · in-place

    Study

    Insertion sort

    Slide each new item into place inside a growing sorted prefix.

    O(n²) worst · O(n) if sorted · stable · in-place

    Study

    Selection sort

    Find the smallest item, put it in front, repeat on the rest.

    O(n²) always · not stable · in-place

    Study

    Merge sort

    Split in half, sort each half, merge the two sorted halves.

    O(n log n) always · stable · O(n) extra

    Study

    Quick sort

    Partition around a pivot, then sort each side.

    O(n log n) avg · O(n²) worst · not stable · in-place

    Study

    Heap sort

    Build a max-heap, then pull out the maximum n times.

    O(n log n) always · not stable · in-place

  E -->|no| G["Quick sort with a random pivot"]

    Key points

    • Bubble, insertion and selection sort are $O(n^2)$ because each of up to $n$ passes can touch the rest of the array.
    • Merge, quick and heap sort reach $O(n log n)$ because they cut the problem into about $log_2 n$ levels of $n$ work.
    • No comparison sort beats $Omega(n log n)$ because it must tell apart all $n!$ input orders, which takes $log_2(n!)$ yes/no comparisons.
    • Stability comes from never jumping over equal items: bubble, insertion and merge sort are stable; selection, quick and heap sort are not.
    • Pick by constraint: nearly sorted → insertion, stable → merge, $O(1)$ memory with a guarantee → heap, fastest on average → quick.
