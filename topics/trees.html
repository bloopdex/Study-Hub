Trees

Six tree structures, from the basic vocabulary to the trees inside databases. Binary search trees keep values ordered for $O(h)$ search; AVL and B-trees keep $h$ small; heaps keep only the minimum or maximum on top.

Why it matters: the height of a tree is the cost of almost every operation on it. Every structure here is a different trick for keeping that height near $\log n$.

    Key points

    • Operations cost $O(h)$ on search trees because they follow one root-to-leaf path.
    • A plain BST can become a chain because nothing stops sorted input from always going the same way.
    • AVL trees guarantee $O(\log n)$ because rotations keep sibling heights within one of each other.
    • Heaps make the min or max $O(1)$ because they only order parents against children, which is cheaper to maintain than full order.
    • B-trees suit disks because many keys per node make the tree just a few levels deep.
