Complexity analysis

Count how the work of an algorithm grows as its input grows. A loop over $n$ items does about $n$ steps; a loop inside it does about $n^2$; halving the input each time needs only about $\log_2 n$ steps. Big-O names that growth and ignores constant factors: $O(n)$, $O(n \log n)$, $O(n^2)$.

Why it matters: every page on this site states a complexity. Knowing what $O(\log n)$ or $O(n^2)$ means in real numbers tells you which algorithm still works when the input grows from a hundred items to a million.

    The three notations: $O(f)$ is an upper bound on the growth, $\Omega(f)$ a lower bound, and $\Theta(f)$ both at once. Best, average and worst case are three different inputs, each of which can be described with any of the three notations.

    Key points

    • Big-O describes growth, not speed, because constants and lower-order terms stop mattering as $n$ grows.
    • Nested loops over $n$ are $O(n^2)$ because the inner body runs $n$ times for each of the $n$ outer steps.
    • Halving gives $O(\log n)$ because $n$ can be halved only about $\log_2 n$ times before reaching 1.
    • The worst case is the usual guarantee because it holds for every input of size $n$.
    • Appending to a dynamic array is amortized $O(1)$ because the rare $O(n)$ copies are spread over many cheap appends.
    • Space complexity counts extra memory because the input itself has to be stored anyway.

    Video talking points

    Use these 5 bullets as your script outline. Say each one in your own words. Do not read them: glance at them and speak.

    1. Hook (10 sec). Ask: why can an algorithm that is faster on 100 items be hopeless on a million?
    2. The big picture (30 sec). Big-O describes how the work grows with the input size $n$, ignoring constants: $O(1)$, $O(\log n)$, $O(n)$, $O(n \log n)$, $O(n^2)$, $O(2^n)$.
    3. Reading code (30 sec). One loop over the input is $O(n)$; a loop inside a loop is $O(n^2)$; halving the input each step is $O(\log n)$; halving levels with a full pass per level is $O(n \log n)$.
    4. How to choose (45 sec). Walk the "Which one to pick?" flowchart on a small piece of code, then compare with the table: at a million items, $n \log n$ is about 20 million steps and $n^2$ is a trillion.
    5. One takeaway (10 sec). For large inputs the growth rate beats every constant factor, so pick the algorithm with the slower-growing curve.
